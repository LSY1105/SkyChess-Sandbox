## 二、架构

```
                    ┌──────────────────────────────┐
   浏览器 ─────────▶│  server.mjs (Node, 无依赖)     │
   player.html      │  · /api/seat/:code  玩家动作   │
   teacher.html     │  · /api/gm         裁判动作   │
                    │  · sessions: Map<席位, 游戏状态> │
                    └──────────────────────────────┘
                         ▲            ▲
              CA / AB / VA / G1 …   全局参数 + 事件
              各自独立状态，互不干扰
```

* **状态全部在服务端内存**（`sessions`），每个席位一份完整游戏状态。
* 玩家之间的操作**完全隔离**：改运价 / 开航线 / 排班 / 投资 / 提交回合，均只作用于本席位。
* 裁判的全局参数（油价、碳价、利率、中转强度）**广播**到所有席位。
* 裁判事件可**定向**（只打某一个席位/某一家航司）或**全局**。
* 裁判可**统一推进**所有席位，也可由各组自己提交。

### 排班规则（与真实游戏一致）

* 每条排班 = **每日 1 班**（季度频次 = 班次数 × 90 天）
* **BH 上限**：短程 775 BH/季，长程 900 BH/季（冰雹等事件可再压低）

* 运价、舱位、货量、燃油、碳成本、中转衔接全部由 `engine.js` 计算

## 六、已修复的关键缺陷（审计发现）

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `#selMkt` 市场下拉从未填充 | 排班功能完全不可用 | 填充已开通航线 |
| 2 | `canAddFlight` 把班次与**自身**比较过站时间 | 每机每航线每天只能飞 1 班（真实为 4–5 班） | 传入新班次起飞时刻正确比较 + 过站/返航窗口 |
| 3 | `pax = min(seatsOffered × freq, D)` 重复乘天数 | 承运量超座位 8 倍，客座率 1334% | 改为 `min(seatsOffered, D)` |
| 4 | 中转旅客直接叠加在已满载的本地客之上 | 总承运 > 可供座位 | 中转只填余量并记录挤出量 |
| 5 | 货舱容量取 `m.cargo`（市场字段不存在） | 货运收入恒为 0 | 改取飞机 `ac.cargo` |
| 6 | 货量需求 `cargo_demand × 90 × freq` 重复乘天数 | 货运量虚高 | 改为 `cargo_demand × 90` |
| 7 | 冰雹 `utilCap = effect.turns`（3）当 BH 上限用 | 容量 3 BH → 无法排任何班次 | 折算 4 BH/日 × 90 = 360 BH/季，独立倒计时 |
| 8 | 火山/大流行用 `effect.turns` 当需求系数 | 火山 ×3、大流行 ×2（与设计相反） | 改用 `effect.demand_mult`（0.55 / 0.5） |
| 9 | 需求倍数/限飞/停飞无到期机制 | 事件永久生效 | 按到期回合清理 |
| 10 | 航司事件用 `a.id === target` 匹配类型字符串 | 冰雹等事件无效 | 同时匹配 id 与 type |
| 11 | 投资/购置无即时反馈 | 用户不知是否生效 | 即时扣款 + 日志 + 提示 |
| 12 | 飞机 id 随机 | 无法稳定引用 | 确定性 id（1,2,3…） |
| 13 | 无班次时无法提交回合 | 回合无法结束 | 允许空回合提交 |

## 七、模型口径（与真实数据对齐）

* 收入 `客运 = 0.926228 × 运价 × 旅客`（R² = 0.983，佣金 7.38%）
* `ASK = 座位 × 频次 × 航段公里`（Lewis Q2/2029 反算 = 报表 17.1MM ✓）
* `ADU = 日班次 × 单程 BH`（Lewis/Simone 双验证 ✓）
* 完整 18 行损益表闭合，残差 = 净财务费用（自有利息 157,318 + ROU 127,698）
* 10 个市场需求模型（K_market × QSI 因子 × 价格弹性）
* 26 种机型目录、19 项 GM 成本参数、4 起事件
* 复盘 7 个真实季度：总误差 −4.16%

## 八、已知边界

* 需求函数的**弹性无法独立识别**（LF=100% 观测仅 3 个且分属不同市场，K 与 ε 共线），
  当前直接采用逆向得到的 API 弹性值。
* Joplin 季节性、Lewis Q1/2028 的负 QSI 区间未建模（复盘残差主要来源）。
* 贷款 / 湿租的完整利息摊还未实现（当前用固定持有成本 + ROU 近似）。
* 真实站点无法做三账号 + 裁判并行操作（对局已结束且无裁判后台账号），
  故多席位能力在本地沙盘实现。

## 九、竞争机制（v2）

沙盘是**竞争教学模拟**：三家航司在**同一市场**争夺同一批旅客。

### 9.1 需求如何切分

```
V_i     = a·ln(p_i) + b·ln(f_i) + c·QSI_i + δ_i        # 航司 i 的效用
share_i = softmax(V)  在该市场的所有航司上                 # 份额之和 = 1
pax_i   = min(seats_i, D_market × share_i)                # 再受座位约束
```

`D_market` 用**市场层面**口径计算（客座加权均价 + 全网总班次），
因此**全网承运 ≤ 市场需求**（不存在重复计量）。

### 9.2 权重来自真实数据

| 权重 | 值 | 来源 |
|---|---|---|
| 价格 `a` | **−0.562** | 真实 `Route Share` 序列反推（与 API 弹性 1.05–1.10 同量级） |
| 班次 `b` | **+1.160** | 同上（班次翻倍份额 +123%） |
| QSI `c` | **+0.086/点** | 同上 |

> **重要**：QSI 不是**市场需求**驱动，而是**竞争份额**驱动。
> 服务品质更高的航司从对手手里抢份额 —— 这与需求总量无关。
> （标定脚本：`rebuild/fit_competition.py`）

### 9.3 竞争确实生效

实测局面（玩家 SIM 3 班/日、$120、QSI 8.0）：

| | 运价 | 班次/季 | QSI | 份额 |
|---|---|---|---|---|
| 玩家 | $120 | 270 | 8.0 | **49.6%** |
| AI 竞品 AB | $118（自动降价） | 360（自动加班次） | 4.2 | **50.4%** |

AB 的低价 + 高频被玩家的 QSI 投资恰好抵消。**不投 QSI 就会被压过去。**

### 9.4 事件对各家影响不对称

冰雹等事件停飞的飞机，**其已排班次作废**（`dropGroundedSchedules`）——
否则该机仍计入班次，事件对被打中的航司就没有真实惩罚。
实测：玩家被冰雹命中 → 该市场班次归零 → 份额塌陷退出，AB 接管 100%。

### 9.5 湿租（真实游戏 CA 开局为租赁 ROU）

| 项 | 值 |
|---|---|
| 押金 | 目录价 2%（≈2 个月租金，贴近业惯例） |
| 季租 | 目录价 11% ÷ 4 |
| 买断 | 目录价 55% |

租赁机不计入自有持有成本（折旧/利息/保险），租金走融资流出。
**教学意义**：宽体机队必须先积累现金才能租 —— 现金不足时 UI 会明确提示所需金额。

### 9.6 竞争机制测试

```bash

                             # 事件影响不对称 / 不同路线不同结局 / 全网守恒
```

## 十、裁判谈判工作台与提案治理

### 10.1 访问与密钥

| 角色 | 地址 |
|---|---|
| 小组 | `http://127.0.0.1:8765/player.html?seat=CA&key=<CA组密钥>` |
| 裁判 | `http://127.0.0.1:8765/teacher.html?key=<教师密钥>` |

密钥首次启动生成于 `sandbox/.sandbox-keys.json`（重启不变）；
教师可用 `GET /api/keys`（持教师密钥）取各组密钥。
**小组只能操作自己的席位**（跨组访问 401）；教师可查看各组状态。

### 10.2 可谈判条款（裁判端 §⑤ 谈判工作台）

定向：燃油价 · 碳价 · 利率 · 中转强度 L · **保险费率** · **燃油套保** · 航线补贴 ·
费用折扣 · **短程过站时间** · 租赁方式/折扣 · 市场级油价/需求倍数 · 飞机回购报价 ·
**投资项每旅客成本与收益** · **情报报价（逐组不同）**

### 10.3 提案机制（小组只能发起，裁判批准方生效）

小组面板 §提案 → 发起；裁判面板 §⑥ 提案审批 → **可修改参数后批准**。

涉及**别组数据、市场规则或罚则豁免**的事项一律走提案：
飞机转让给别组 · 飞机大修 · 公务舱额外乘务员 · 全航线餐饮统一 ·
事件罚则豁免+替代机顶班 · 主题化运营 · 固定价采购项 · 机库租赁

### 10.4 真实机制要点（依据 7 份小组谈判纪要）

- **燃油套保是两档固定方案**（非连续可谈）：
  Swap $5 万 → 结算价**双向锁定** $2.63/加仑；Call $35 万 → 结算价**上限** $2.43/加仑
- **过站时间**是 15 分钟档位：45 分钟免费且保留货运，30 分钟须放弃货运，长程固定 120
- **飞机大修**：只需运营上季一半 BH，完成后出售**多 $500,000**
- **投资项四段结构**：Initial / Annual / **Costs per passenger** / **Revenue per passenger**
- **受损机豁免**：经裁判批准可由替代机顶班，不按满编罚
- **大飞机配小航线必亏**：用情报的日潜在运量对比机型座位数（Lewis 150–200/日 vs G250 272 座）

详见 `真实机制对照.md`（逐条对照 + 证据出处 + 实现状态）。
