### 8.3.1 【11-20】根因排查：小组端「永远不同步」

**根因（实测定位，非推断）**
`player.html` 的轮询写在**经典内联 `<script>`** 里并调用 `refresh()`，但 player.html 全文**没有 `refresh()`**（真实函数是
`<script type="module">` 里的 `load()`）→ `ReferenceError` 被 `try/catch` **静默吞掉** → **小组端轮询从未成功执行过一次**（setInterval 回调从未触发）。
于是小组端与裁判端**永久不同步**：裁判改参数 / 放资金 / 开关投资 / 结算，小组端全看不到，只能手动刷新页面。
**这一条足以解释全族现象**：「点了没反应」「数据不更新」「报表无数据」「裁判开关不生效」「必须手动刷新才看得到」。
裁判端同稿的 `refresh()` 在模块内、且 `setInterval(refresh, 5000)` 也在模块内 → 裁判端一直正常（**两端不对称**，是本次缺陷的关键）。

**排查手法（可复用）**：Chrome CDP 探针（页面内 `window.__pollDbg` / `__loadDbg` / `__renderDbg`）+ 服务端 `console.error` 探针 + 逐项二分。
关键诊断：`cdp.until(fn)` 会把 fn **序列化**后在页面里求值 → **闭包变量全部失效** → 每次都抛 ReferenceError，
`until()` 永远返回 null。若需闭包值必须用 `cdp.call(fn, arg)` 显式传参。

**本轮修复（4 处）**

| # | 缺陷 | 修法 | 文件 |
|---|---|---|---|
| 1 | 小组端轮询调用不存在的 `refresh()` | 轮询移进 `<script type="module">`、改调 `load()`；闸门改为「正在打字 / 正在按下的按钮才延后，下个 tick 自动重试」，间隔 4s→2s | `sandbox/player.html` |
| 2 | 重绘无条件重建 `<select>` → 已选项打回第一项、正在展开的下拉被关掉 | 新增 `fillSel()`：选项集没变就不重建，并保留当前值；用到 3 个 select | `sandbox/player.html` |
| 3 | API 响应无 `Cache-Control`（静态文件有 `no-store`） | API 分支补 `Cache-Control: no-store` | `sandbox/server.mjs` |
| 4 | 未结算时报表 Summary 页签整页「—」 + 11px 灰小字 → 学员判成「报表无数据」 | 改为 13px 橙色告警条「⚠ 本季尚未结算 · …」，并去掉文案里的字面 markdown 星号 | `sandbox/reports.js` |

### 8.3.2 【11-20】裁判端「整页闪动」：改成「先取数、后一次性替换」

**测量方法（可复用，比「人眼看闪动」可靠）**：用 CDP 在页面里装 **rAF 逐帧采样**，每帧记录每个带 id 元素的「可见文本是否为空」，
只有「由非空变空」才算**被画出来的空态**（真正的闪动）。
判据用「可见文本」而不是 `childElementCount`：日志只有 1 条时没有 `<br>`，子元素数为 0 但文字还在 → 人眼看得到，不算空（测量假阳性）。

**根因**：裁判端有 **4 处「先清空 → `await` 拿数据 → 再填」」**的写法。
清空与填充之间有一个 `await`（网络请求）→ 浏览器**会把空白的面板画出来**，然后再填上 → 学员看到面板消失再出现 = 「整页闪动」。
（同一个任务里清空 + 填充**同步**完成时不会被画出来，所以其它 20+ 面板不闪。）

| 位置 | 原写法 | 现在 |
|---|---|---|
| `#tblRules` 分季规则表 | 清空 → 表头 → `await` 拿规则 → 追行 | 先 `await` 拿规则，再组装 fragment 一次性替换 |
| `#tblSeats` 席位表 | 清空 → 表头 → **循环里每席 await** → 逐行追加 | 先把三组数据全取回来，再统一建行 + `replaceChildren` |
| `#propList` 提案列表 | 清空 → **循环里每席 await** → 逐个追加 | 同上，统一建后一次性替换 |
| `#hackPanel` 网络攻击面板 | 清空 → **循环里每席 await** → 追加 | 同上 |

**实测结果**（隔离实例 + 真实 Chrome，诱发结算后 rAF 逐帧采样 10 秒）：
修复前 **2 帧面板被画空**（`#hackPanel` 1→0、`#log` 1→0，后者为采样假阳性）；修复后 **0 帧**。

**永久护栏**（`sandbox/browsertest.mjs`，现 41 条）：「裁判端状态变化后不得出现被画成空的面板」
—— rAF 逐帧采样，任何面板「由非空变空」即判红。**以后再闪，护栏会变红，不再靠「人眼看」。**
### 8.3.3 【11-20】同机排班占用区间（回程路上不得再排去程）

**用户实测场景**：同一架飞机排了 09:00 的去程，默认回程占用 11:32→13:04（机在回程航段），
却能再排一班 **12:00** 的去程 → **同机同时出现在两地**。

**根因（两个错对字面与代码不一致）**：
`canAddFlight` 的占用判定只比 **两个起飞时刻之差**（`Math.abs(depNew - s.departure) < minGap`），
而 `minGap` 只用了 **单程 + 过站**（注释写的是「去-回-周转」整轮往返时长，代码遗漏了一条）。
**完全没有看上一班的回程段** → 上一班还在飞、回程航上，下一班去程就被放行。
模型上机器的「可再排班时刻」取的是 **回程起飞**（`blkMin = retDepMin`）——机器在回程航段就被当作已释放，
甚至 **甘特图的块宽**（`blockUntil`）也画成了「已归位」的样子——规则与可视化同源。

**修法（占用区间模型，唯一真源）**：
每班占用 **[起点, 回程到达]**（机回到廊桥才算归位），两个占用区间不得重叠，且上一班回程落地后**还要过一个过站时间**才能再推。

| 位置 | 改动 |
|---|---|
| `game.js` 新增 `checkOccupancy()` | 占用区间校验（唯一真源，导出供其他处调用） |
| `game.js` `canAddFlight()` | 删掉「两个起飞时刻之差」判定，改用占用区间判定 |
| `server.mjs` `addFlight()` | `blkMin` 从「回程起飞」改为「回程到达 + 过站」（甘特图块宽也因此正确） |
| `server.mjs` `setReturnFlight()` | 回程时刻改动后**重新校验**同机其它班次（拖晚回程会撞下一班），并重算 `blockUntil` |

**实测（正式实例 8765）**：
```
09:00 排班 = ok
该班次: 起点 09:00 → 到达 10:32 → 回程 11:32 → 回程到达 13:04 | blockUntil 14:04
同机 12:00 再排去程 = 与该机已有班次时间重叠（SIM 09:00→13:04，该机在航/回程路上）   ← 已拒
同机 14:30 再排去程 = ok                                                        ← 允许
```
§ 11-20 后续（过站补回）：上面那版修复只留了「占用不重叠」，实测发现**过站判定被误删**：13:04 落地、13:04 就能再飞，而「过站」= 下客+清洁+上客（基准 60 分钟）是飞机停在廊桥时的地面保障时间 → 回程落地后必须再等一个过站才能飞。
已恢复：`checkOccupancy()` 回归「重叠不可」+「间隔一个过站」两条判定。
实测（正式实例）：13:04 拒、13:30 拒、**14:04 允许**（落地 13:04 + 过站 60）。
因此「缺分钟归一化」旧测试的 12:00 排班（旧模型依赖已废的占用规则）改为用**未排班飞机**。
**回归测试**（`sandbox/submittest.mjs`，现 9 条）：「同机回程路上不得再排去程」、「回程时刻拖晚撞下一班必须被拒」、「回程落地后必须过完过站时间才能再飞」。

### 8.3.4 【11-20】裁判端「各航司过站时间」机制检查与修复 + 小组端「可再排班」提示

**机制存在**：裁判端「分组配置矩阵」有「过站(分)」条目（teacher.html），逐组下发 `negotiate` → `g.negotiation.turnaroundMin`（**按席位＝逐航司**）。引擎 `turnaroundFor()` 按该组经营定位取用；长程机型固定 120 分钟不可谈。

**缺陷 1（机制空转：谈了等于没谈）**：`turnaroundFor` 额外要求 `neg >= base`，而 base=60 → 裁判谈 30/45 分被**静默忽略**（引擎仍用 60），但服务端照收不误、谈判记录还写着 45。
实测：谈 45 → 排班实际用过站仍是 60。
→ 修：任一允许档位（30/45/60/75/90）均生效。

**缺陷 2（30 分钟档无代价＝白送）**：数据写明「45 分钟档免费保留货运 / 30 分钟档须放弃货运」，但**放弃货运从未实现**。
→ 修：新增 `cargoAllowed(g)` —— 30 分钟档 → 该组货运能力归零（`cargoCap` / `ratedPerFlight` = 0 → 货运收入为 0）；45 分钟档免费保留货运。
→ 裁判端矩阵「过站(分)」行补说明：45 免费保留货运；30 须放弃货运（该组不再载货）；长程固定 120 不可谈。

**缺陷 3（清空不回基线）**：裁判把输入框清空 → 服务端按 `Number(null)=0` 判「档位不适用」而拒绝 → **无法把档位退回基线**。
→ 修：空值跳过档位校验 → 写回 null → 回到基线 60。

**附带修掉一个我自己写的坑**：`Number(null) === 0` → 第一版 `cargoAllowed` 把「未谈判」的组（turnaroundMin=null）误判为 30 分档 → **全场货运归零**，demandtest 收入 -2.85% 变红。已修（先判 null/空串再转数），并补单元断言「未谈判 → 保留货运」。

**小组端提示（用户要求）**：排班表新增「**可再排班**」列 = 回程到达 + 该组过站时间（这架飞机最早能再排下一班的时刻）；同时修掉原来 tooltip 里那句错的「下一班起点可再晚 2–4 小时（联程中转窗口）」（与实际规则无关）。经营要点的「过站保障」改为显示**生效值**（含裁判谈判档位）。

**实测（正式实例 8765，裁判谈 45 分）**
```
表头: 飞机|航班|起飞|到达|过站时间|回程起飞|回程到达|可再排班|市场|货量|操作
数据: APT100 09:00 → 到达 10:32 → 回程 11:17 → 回程到达 12:49 → 可再排班 13:34
                                                          （12:49 + 过站 45 = 13:34）

```

**回归测试**：`submittest` 增 2 组（裁判谈定的档位真正生效 45 / 30 分档放弃货运 + 未谈判保留货运 + 清空档位回基线）；`browsertest` 增「排班表有『可再排班』列」。
