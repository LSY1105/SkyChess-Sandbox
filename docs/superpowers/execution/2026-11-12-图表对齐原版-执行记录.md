## 3. 回滚路径（按需要选一条）

### 3.1 单个 Task 不满意 → 回退那一个提交
```bash
git log --oneline -12                    # 找到该 Task 的提交
git revert <sha>                        # 生成反向提交（安全，历史保留）
node runtests.mjs                       # 确认仍全绿
# 再推一次远端（见 §1 的推送方式）
```

### 3.2 整轮回退到基线 → 回到 `c2dca7a`
```bash
git reset --hard c2dca7a                # 本地回到基线（未推送的提交全部丢弃）
node runtests.mjs                       # 确认 324 全绿
```
> 远端已是 `0f83a8e`（= 基线内容），**只要不回滚远端历史，远端始终有可恢复副本**。

### 3.3 远端也要回退 → 用仓库自带的历史重写工具
```bash
cd sandbox && python rewrite_history.py   # 仓库自带（11-11 提交引入），按远端历史重写
```
> 远端历史**已被重写过多次**（旧 SHA 失效）→ 旧 clone 需 `git fetch origin && git reset --hard origin/main`。

### 3.4 只想看改动、暂不动代码
```bash
git diff c2dca7a -- sandbox/reports.js   # 看某个文件的累计改动
git diff c2dca7a --stat                   # 看全部改动统计
```

### 3.5 出问题但不确定从哪开始
```bash
git bisect start
git bisect bad <坏掉的提交>
git bisect good c2dca7a
git bisect run node runtests.mjs          # 每次提交跑一次全量，自动定位
git bisect reset
```

## 4. 已知易错点（都踩过）

| # | 易错 | 说明 |
|---|---|---|
| 1 | **清单不用 `-z`** | `git ls-files` 默认八进制转义中文路径 → 清单里文件名失真 → 推送中断（本次已踩过一次） |
| 2 | **推送消息带空格** | PowerShell 会把消息拆成多个参数 → 把消息片段当成清单路径（本次已踩过一次） |
| 3 | **密钥入库** | 历史上两次把隔离测试密钥提交并推送 → 每次推送前确认 `.gitignore` 覆盖 4 类通配（`.sandbox-keys.json` / `.admin-key` / `*.pem` / `*.key`） |
| 4 | **改完不重启 8765** | `server.mjs` / `game.js` 改动后必须重启正式服务，否则测到旧逻辑 |
| 5 | **内联 HTML/JS 改完不 check** | 必须 `node --check`（项目既有做法：抽出内联脚本再 check） |
| 6 | **模块内引用页面别名** | `reports.js` 内部只能引用本模块导出（§10 项目同步文档 坑②） |
| 7 | **轮询整块重建** | 页签按钮只创建一次、只切 `.on`；不要 `innerHTML=''` 重建整个 Reports 区（坑⑫） |
| 8 | **NaN 上屏** | 新增数值渲染必须走 `el()` / `money()` / `num()` / `pct()`，非有限值显示 `—`（11-11 三次事故后立的规） |
| 9 | **paneltest 偶发失败** | 已知 flaky（单独跑必过）→ 先单独跑确认是抖动还是真缺陷 |
| 10 | **报告结构变更影响消费方** | `report` 新增字段是**纯增量**，但仍需回归 `submittest` / `flitecontest` / `uitest` |
